# Proposal

## Why

Loans, renewals, holds and fines all need a reader: someone with a network-wide library card and a
category that sets how many books they may borrow and for how long. This change introduces readers
and their categories so `add-loans` can check limits and compute due dates without reshaping
anything.

## What Changes

- **Reader categories from configuration.** Three categories with their loan limit and loan period:
  `ADULT` (5 loans / 21 days), `STUDENT` (10 / 30), `CHILD` (3 / 14). The set of categories and their
  numbers live in configuration, not in the database or in code. A read-only endpoint lists them.
- **Age restriction per category.** A category may define an age limit. `CHILD` is allowed only for
  readers younger than 14 on the current date. `ADULT` and `STUDENT` have no age check.
- **Reader registration.** New REST API to register a reader. Decisions fixed in this proposal:
  - **Card number is generated by the system** on registration, format `LN-` followed by at least
    6 digits, zero-padded (`LN-000001`, `LN-000002`, ...). It is unique across the network, cannot be
    set by the client and never changes.
  - **Required fields:** `firstName`, `lastName`, `dateOfBirth` (not in the future), `category`, and
    at least one contact: `email` or `phone`. Both contacts may be given. Email is not unique (family
    members may share one).
- **Reader update.** `PUT` replaces name, date of birth, contacts and category with the same
  validation as on create. **Category can be changed**; the age restriction is checked again when the
  category or the date of birth changes. The card number cannot be changed.
- **Reader lookup and search.** Get a reader by id; search with one optional `q` parameter: if `q`
  looks like a card number it matches that card exactly (case-insensitive), otherwise it matches a
  case-insensitive substring of the first name, last name or full name. Optional `category` filter.
  Results are paginated like other list endpoints.

## Capabilities

### New Capabilities

- `reader-categories`: reader categories with their loan limit, loan period and optional age limit,
  defined in configuration and listed through the API.
- `readers`: reader records with a system-generated card number: registration, update, lookup and
  search.

### Modified Capabilities

None. Pagination follows the existing "Paginated list responses" requirement in `catalog`.

## Out of scope

- Loans, returns, and enforcing the category loan limit or loan period (`add-loans`). This change
  only stores and exposes the numbers.
- Fines, unpaid-fine blocking and any other reader blocking (`add-fines`). Readers have no status.
- Notifications to readers (`add-notifications`); contacts are only stored.
- Deleting or deactivating readers, card expiry, card reissue or a "lost card" flow.
- Re-checking age of existing `CHILD` readers when they turn 14 (no job; the nightly job does not
  cover it either). A reader stays `CHILD` until the librarian changes the category.
- Managing categories through the API (create, rename, change limits). Categories change only by
  editing configuration.
- Address, documents, photo and other personal data.
- Authentication and authorization.

## Configuration

New `@ConfigurationProperties` prefix `library.readers`:

| Property | Default | Meaning |
|---|---|---|
| `library.readers.categories.adult.loan-limit` | `5` | Max loans at the same time |
| `library.readers.categories.adult.loan-period-days` | `21` | Loan period in days |
| `library.readers.categories.student.loan-limit` | `10` | |
| `library.readers.categories.student.loan-period-days` | `30` | |
| `library.readers.categories.child.loan-limit` | `3` | |
| `library.readers.categories.child.loan-period-days` | `14` | |
| `library.readers.categories.child.max-age-exclusive` | `14` | Reader must be younger than this (full years) on the current date; absent = no age check |

Category keys are written in lower case in configuration; the API value of `category` is the key in upper case (`adult` → `ADULT`). The application fails to start if there are no
categories or if a limit, period or age is not positive.

## Impact

- New domain package `readers` (categories configuration, reader entity, service, controller, DTOs).
- A `Clock` bean in `common` (the first business rule that needs the current date), also used for
  `dateOfBirth` validation.
- New Flyway migration `V3__readers.sql`: `reader` table and a sequence for card numbers.
- New endpoints `/api/readers` and `/api/reader-categories`, visible in OpenAPI.
- New error codes `READER_NOT_FOUND` and `READER_CATEGORY_NOT_ALLOWED`.
