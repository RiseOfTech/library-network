# Spec Delta

## Purpose

Lets librarians register readers of the library network, each with one network-wide library card,
keep their personal and contact data up to date, and find them by card number or name.

## ADDED Requirements

### Requirement: Register a reader
The system SHALL allow registering a reader with `firstName`, `lastName`, `dateOfBirth`, `category`
and at least one of `email` and `phone`. The response contains the reader with its generated `id`
and `cardNumber`.

#### Scenario: Reader is registered
- **WHEN** a client sends `POST /api/readers` with `{"firstName": "Anna", "lastName": "Petrova", "dateOfBirth": "1990-05-17", "category": "ADULT", "email": "anna@example.org"}`
- **THEN** the system responds `201 Created` with a `Location` header pointing to `/api/readers/{id}` and a body containing `id`, `cardNumber`, `firstName`, `lastName`, `dateOfBirth`, `category`, `email` and `phone` (`null`)

#### Scenario: Reader with phone only
- **WHEN** a client sends `POST /api/readers` with valid data, `phone` `+7 900 123-45-67` and no `email`
- **THEN** the system responds `201 Created` with `phone` `+7 900 123-45-67` and `email` `null`

#### Scenario: Missing required fields
- **WHEN** a client sends `POST /api/readers` with a blank `firstName`, without `lastName`, without `dateOfBirth` or without `category`
- **THEN** the system responds `400 Bad Request` with code `VALIDATION_FAILED` and each missing field listed in `errors`

#### Scenario: No contact given
- **WHEN** a client sends `POST /api/readers` with valid data but neither `email` nor `phone`
- **THEN** the system responds `400 Bad Request` with code `VALIDATION_FAILED` and `email` listed in `errors`

#### Scenario: Invalid contact format
- **WHEN** a client sends `POST /api/readers` with `email` `not-an-email` or `phone` `call me`
- **THEN** the system responds `400 Bad Request` with code `VALIDATION_FAILED` and the invalid field listed in `errors`

#### Scenario: Date of birth in the future
- **WHEN** today is 2026-11-04 and a client sends `POST /api/readers` with `dateOfBirth` `2026-11-05`
- **THEN** the system responds `400 Bad Request` with code `VALIDATION_FAILED` and `dateOfBirth` listed in `errors`

#### Scenario: Same email for two readers
- **WHEN** a reader with `email` `family@example.org` exists and a client registers another reader with the same `email`
- **THEN** the system responds `201 Created`; email is not required to be unique

### Requirement: Card number is generated by the system
The system SHALL assign every new reader a unique card number `LN-` followed by at least 6 digits,
zero-padded, in increasing order of registration. Clients cannot set or change it.

#### Scenario: Card numbers are sequential and unique
- **WHEN** a client registers two readers one after another
- **THEN** both responses are `201 Created`, both `cardNumber` values match `LN-` followed by 6 or more digits, and the second number is greater than the first

#### Scenario: Card number in the request is ignored on registration
- **WHEN** a client sends `POST /api/readers` with valid data and `"cardNumber": "LN-999999"`
- **THEN** the system responds `201 Created` with a system-assigned `cardNumber`, not `LN-999999`

#### Scenario: Card number in the request is ignored on update
- **WHEN** a client sends `PUT /api/readers/{id}` with valid data and a different `cardNumber`
- **THEN** the system responds `200 OK` with the reader's original `cardNumber`

#### Scenario: Concurrent registrations get different numbers
- **WHEN** two clients send `POST /api/readers` at the same time
- **THEN** both responses are `201 Created` with different `cardNumber` values

### Requirement: Update a reader
The system SHALL allow replacing `firstName`, `lastName`, `dateOfBirth`, `category`, `email` and
`phone` of an existing reader, with the same validation as on registration. The `cardNumber` stays
unchanged.

#### Scenario: Reader is updated
- **WHEN** a client sends `PUT /api/readers/{id}` with a new `lastName`, a new `email` and `category` `STUDENT` for an existing `ADULT` reader
- **THEN** the system responds `200 OK` with the updated reader, `category` `STUDENT` and the original `cardNumber`

#### Scenario: Update removes every contact
- **WHEN** a client sends `PUT /api/readers/{id}` with neither `email` nor `phone`
- **THEN** the system responds `400 Bad Request` with code `VALIDATION_FAILED` and the reader is unchanged

#### Scenario: Updating an unknown reader
- **WHEN** a client sends `PUT /api/readers/{id}` for an id that does not exist
- **THEN** the system responds `404 Not Found` with code `READER_NOT_FOUND`

#### Scenario: Concurrent updates of one reader
- **WHEN** two clients read the same reader and both send `PUT /api/readers/{id}` at the same time
- **THEN** one request responds `200 OK` and the other either `200 OK` applied after it or `409 Conflict` with code `CONCURRENT_MODIFICATION`; the stored reader equals one of the two requests, never a mix of both

### Requirement: Get a reader
The system SHALL return a single reader by id.

#### Scenario: Get a reader by id
- **WHEN** a client sends `GET /api/readers/{id}` for an existing reader
- **THEN** the system responds `200 OK` with the reader

#### Scenario: Get an unknown reader
- **WHEN** a client sends `GET /api/readers/{id}` for an id that does not exist
- **THEN** the system responds `404 Not Found` with code `READER_NOT_FOUND`

### Requirement: Search readers
The system SHALL return readers matching an optional `q`: if `q` has the card number form (`LN-` and
digits, any case) it matches that card exactly, otherwise a case-insensitive substring of the first
name, last name or "first last" full name. Optional `category` filter. Without filters all readers
are returned. Ordered by last name, first name, and paginated.

#### Scenario: Search by card number
- **WHEN** a reader with card `LN-000042` exists and a client sends `GET /api/readers?q=ln-000042`
- **THEN** the system responds `200 OK` with exactly that reader in `items`

#### Scenario: Card number that does not exist
- **WHEN** no reader has card `LN-999999` and a client sends `GET /api/readers?q=LN-999999`
- **THEN** the system responds `200 OK` with an empty `items` and `totalElements` 0

#### Scenario: Search by name fragment
- **WHEN** readers "Anna Petrova", "Petr Ivanov" and "Olga Sidorova" exist and a client sends `GET /api/readers?q=petr`
- **THEN** the system responds `200 OK` with "Petr Ivanov" and "Anna Petrova" in `items`, in that order (by last name)

#### Scenario: Search by full name
- **WHEN** a client sends `GET /api/readers?q=anna petr`
- **THEN** the system responds `200 OK` with "Anna Petrova" in `items`

#### Scenario: Filter by category
- **WHEN** readers of categories `ADULT` and `CHILD` exist and a client sends `GET /api/readers?category=CHILD`
- **THEN** the system responds `200 OK` with only `CHILD` readers in `items`

#### Scenario: Paginated reader list
- **WHEN** 25 readers exist and a client sends `GET /api/readers?page=2&size=10`
- **THEN** the system responds `200 OK` with 5 `items`, `page` 2, `size` 10, `totalElements` 25 and `totalPages` 3

#### Scenario: Page size out of range
- **WHEN** a client sends `GET /api/readers?size=0`
- **THEN** the system responds `400 Bad Request` with code `VALIDATION_FAILED`
